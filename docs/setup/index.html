BEFORE LESSON 01

Connect once. Practice with confidence.

Use your existing Azure SQL free-offer database named InterviewLab. No additional Azure resources are needed for this course.

1. Connect in SSMS

Server typeDatabase Engine
ServerYour logical server’s fully qualified name: <your-server>.database.windows.net
AuthenticationMicrosoft Entra MFA; sign in with your configured administrator account
DatabaseInterviewLab, in Connection Properties / Connect to database
EncryptionStrict in current SSMS; keep Trust server certificate unchecked

The server firewall must allow your current public IP. If your network or VPN changes, update that single-IP rule. A paused database can take time to wake; retry the connection.

Microsoft: connect with Entra authentication ↗

2. Create the dataset

  1. Confirm the SSMS database selector says InterviewLab.
  2. Download and open 00-setup.sql, then execute it once.
  3. Run 01-verify.sql. Expect “All seed checks passed”.
  4. Start lesson 01. Run whole solution scripts when they contain variables, transactions, or GO separators.

Setup never drops existing tables. If the lab schema already exists, inspect your existing work rather than rerunning setup. The exercises assume the original seed values; the verification script checks the main baseline counts and totals.

3. Keep the free-offer safeguards

The free allowance is 100,000 vCore seconds, 32 GB of data, and 32 GB of backup storage per database per month. With exhaustion behavior AutoPause, the database pauses when its allowance is used, until the next calendar month. This is separate from idle auto-pause.

This read-only CLI command checks an existing database. Replace the resource group and server placeholders before running it:

az sql db show --resource-group <your-resource-group> --server <your-server> --name InterviewLab --query "{useFreeLimit:useFreeLimit,freeLimitExhaustionBehavior:freeLimitExhaustionBehavior}"

Expect useFreeLimit: true and freeLimitExhaustionBehavior: AutoPause. Disconnect SSMS and Object Explorer when finished. Avoid enabling paid add-ons or changing the database to BillOverUsage.

What this environment supports

All course exercises target Azure SQL Database and T-SQL. Core examples also fit modern SQL Server, but connection settings, permissions, isolation defaults, and service-level features may differ. Azure SQL Database is not a full SQL Server instance: SQL Server Agent, local file access, and ordinary cross-database USE workflows are outside this course.
